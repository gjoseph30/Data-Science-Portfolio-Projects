# Customer Churn Big Data Analytics Pipeline

## Overview

This project designs and implements an end-to-end big data analytics pipeline for predicting customer churn in the banking industry.

The project integrates multiple technologies from the Hadoop ecosystem to demonstrate data ingestion, distributed storage, SQL-based querying, machine learning, NoSQL storage, and pipeline verification.

## Business Problem

Customer churn occurs when customers discontinue their relationship with a business. For financial institutions, identifying customers who may leave can support retention analysis and help organizations better understand factors associated with customer attrition.

The objective of this project was to build a distributed analytics workflow capable of ingesting customer data, processing it through the Hadoop ecosystem, applying machine learning, and storing model evaluation results for later retrieval.

## Dataset

The Bank Customer Churn dataset contains 10,000 customer records.

Available attributes include:

- Credit score
- Geography
- Gender
- Age
- Tenure
- Account balance
- Number of products
- Credit-card ownership
- Active-member status
- Estimated salary
- Customer churn status

The `Exited` field serves as the target variable and indicates whether a customer left the bank.

## Pipeline Architecture

The implemented pipeline follows this workflow:

**GitHub Dataset → Apache NiFi → HDFS → Hive → Spark MLlib → HBase → Verification**

### Apache NiFi

NiFi retrieves the customer churn dataset from GitHub and automates its transfer into Hadoop Distributed File System.

### HDFS

HDFS provides distributed persistent storage for the ingested dataset and makes the data available to downstream Hadoop components.

### Apache Hive

Hive provides a structured SQL interface for the data. A managed table was created for the customer records, and validation and aggregation queries were used to verify successful ingestion and schema interpretation.

A record-count query confirmed that all 10,000 customer records were successfully loaded.

### Spark MLlib

Spark MLlib performs the machine-learning stage of the pipeline. Customer attributes are prepared for modeling, categorical variables are indexed, features are assembled, and a Logistic Regression classifier is trained to predict customer churn.

### HBase

Model evaluation results generated by Spark are written to HBase, demonstrating how analytical output can be persisted in a distributed NoSQL database.

HBase scan operations were used to verify that the results were successfully stored.

- Hive database and table creation

- Feature-vector construction

- Machine-learning model evaluation
- HBase table creation
- Programmatic storage of model metrics
- HBase scan verification

## Challenges

The project required integration across several independent Hadoop ecosystem technologies.

One major challenge was resource management within the virtual-machine environment. Limited CPU and memory made it difficult to operate all services simultaneously. NiFi was therefore stopped after ingestion to free resources for Hive, Spark, and HBase.

Additional challenges included configuring connections between Hadoop components, maintaining consistent data formats, and validating successful data movement at each stage of the pipeline.

## Key Takeaways

The completed workflow demonstrates how multiple distributed technologies can be integrated into a single analytics pipeline.

Rather than performing machine learning as an isolated task, the project connects data acquisition, distributed storage, SQL querying, predictive modeling, and NoSQL result persistence.

Successful retrieval of the model evaluation metrics from HBase verified that the pipeline operated from initial ingestion through final analytics storage.
